# Tier-1 golden set: FEVER

Per CLAUDE.md's golden set section: "Tier 1 -- built from public sources (FEVER-style
data...). Tests claim-vs-framing and the core mechanic. Needs nothing from the owner.
Cannot test defensible compression." This is that tier.

## Source

FEVER (Fact Extraction and VERification), Thorne et al., University of Cambridge, 2018.
185,445 claims, each generated by altering a sentence from Wikipedia and then verified
by an annotator (without seeing the source sentence) as `SUPPORTS`, `REFUTES`, or
`NOT ENOUGH INFO`, with gold evidence sentences recorded for the first two.

- Canonical release: <https://fever.ai/dataset/fever.html>
- Licence: **CC BY-SA 3.0**, per the schema.org metadata on that page
  (`"license": "https://creativecommons.org/licenses/by-sa/3.0/legalcode"`).
- Paper / DOI: <https://doi.org/10.5281/zenodo.4925954>

FEVER's own release ships claims and evidence as `(wikipedia_page, sentence_id)`
pairs against a separate `wiki-pages.zip` dump -- it does not ship the evidence
*text* inline. Rather than fetch and index that dump, this uses a HuggingFace Hub
mirror that has already joined each claim's gold evidence ids to their Wikipedia
sentence text:

- Mirror used: **`Dzeniks/fever_3way`** on the HuggingFace Hub, `validation` split
  (9,999 rows, exactly 3,333 per label -- FEVER's own official 3-way-balanced
  paper-dev set, `paper_dev.jsonl`).
- The mirror's own repo card states an MIT licence for its packaging; the
  *content* is FEVER's, so CC BY-SA 3.0 governs the claims and evidence text
  themselves (a Wikipedia derivative). This file records both because they answer
  different questions -- one covers the data, the other the repackaging.
- `datasets` (HuggingFace) was installable in this workspace ad hoc
  (`uv run --with datasets ...`) and the Hub was reachable from this machine at
  build time -- see "Building the cache" below. It is **not** a permanent
  dependency of `jfl_evals`.

## What was built

`packages/evals/scripts/build_fever_dataset.py` reads the mirror above and writes
`packages/evals/data/fever_slice.jsonl`, the file the eval and its tests actually
read. Nothing downstream of that file ever touches the network.

- **210 items**, exactly balanced: 70 `SUPPORTS`, 70 `REFUTES`, 70 `NOT ENOUGH INFO`.
- Label mapping (CLAUDE.md's drift taxonomy: "the standard supported / refuted /
  not-enough-evidence split ... public FEVER-style data maps onto it directly"):
  - `SUPPORTS` -> expected verdict `supported`
  - `REFUTES` -> expected verdict `unsupported`
  - `NOT ENOUGH INFO` -> expected verdict `review`
- **Sampling method**: for each label, shuffle that label's pool of the validation
  split with `random.Random(20260901)` (seed = today's date at the start of this
  work), then take the first 70 items whose evidence actually resolved to text.
  `SUPPORTS`/`REFUTES` items with no resolved evidence (the mirror occasionally
  fails to join a sentence id) are skipped, never kept with invented evidence; in
  this run, **zero** were skipped -- all 210 kept items are the first 70-per-label
  drawn. `NOT ENOUGH INFO` items are kept with their (legitimately empty)
  evidence list unconditionally -- FEVER's NEI items have no evidence by
  construction, and an empty corpus for those items is the correct golden-set
  entry, not a gap.
- Evidence sentences average 0.74 per item overall (0 for every NEI item, ~1.05
  for SUPPORTS/REFUTES items that do have evidence); max 2 sentences for any one
  item. Small, per-item corpora, exactly matching `check_text`'s per-user corpus
  shape -- never the whole golden set stuffed into one context.
- Claim and evidence text is lightly de-tokenized (FEVER's release is PTB-tokenized:
  `-LRB-`/`-RRB-`, space-separated punctuation and possessives) so the corpus reads
  as prose rather than as a parser's intermediate format. This is cosmetic --
  see the script for the exact substitutions -- and changes nothing about what a
  claim or evidence sentence asserts.

### Building the cache

Not run automatically; this is provenance, not part of the eval:

```
uv run --with datasets python packages/evals/scripts/build_fever_dataset.py
```

Re-running it is only as reproducible as the upstream Hub mirror -- the seed fixes
*which* items get chosen from whatever the mirror serves, not a byte-identical
network response. The committed `data/fever_slice.jsonl` is the actual golden set
this eval uses; the script does not need to be re-run to use it.

## What this dataset cannot test

Per CLAUDE.md: "Cannot test defensible compression." FEVER is Wikipedia
fact-verification, not career claims. It exercises:

- the core grounding mechanic (does a verdict correctly follow from a small,
  explicit evidence set, in either direction), and
- claim-vs-framing at a basic level (every FEVER claim is a factual assertion by
  construction, so the gate calling one `kind="framing"` is a signal worth
  watching -- see `jfl_evals.scoring`'s `framing_rate`, tracked but never a
  headline number for exactly this reason).

It says **nothing** about the drift taxonomy's evidence-dependent labels
(`scope_inflation`, `ownership_inflation`, `outcome_attribution`, `strategy_scope`,
`causality`) -- those all turn on what a CV's corpus documents about *scope*,
*ownership*, and *attribution*, categories that do not exist in Wikipedia
fact-verification. It also cannot test defensible compression: a CV bullet that
legitimately summarizes several corpus facts into one claim. Tier 2 (10-15 items
from the owner's own corpus, per CLAUDE.md, optional and not built here) is the
only place those get covered.

One further, concrete limitation the first real smoke-test run surfaced (see
`README.md`): at least one FEVER claim in this slice ("Dark matter is
theoretical.") reads, to the model, as more like a general/definitional statement
than a checkable factual assertion, and the gate called it `kind="framing"` even
though FEVER's own annotators treated it as a checkable claim with insufficient
evidence. FEVER's claim/evidence distinction and this gate's claim/framing
distinction are similar but not identical categories; a nonzero `framing_rate` on
this dataset is not purely a gate defect, and should be read as "worth a look",
not "the gate is broken," until enough real runs establish a baseline rate.

**Do not adjust these 210 items, their labels, or the sampling method to make a
later gate run score better.** CLAUDE.md's golden set discipline applies to tier 1
exactly as it does everywhere else in this project.
