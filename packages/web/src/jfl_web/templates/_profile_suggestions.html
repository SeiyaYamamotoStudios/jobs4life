{# The CV-read profile settings panel, rendered both inside /profile and on its own by GET /profile/suggestions/{id}. The polling trigger lives on this element and only while the run is `pending`, so a finished run stops the poll by virtue of what came back: there is no timer to cancel and no client-side state to get out of step with the row. `hx-swap="outerHTML"` because the element replaces itself. Same trick as `_capability_clusters.html`. `suggestions` is a `jfl_web.profilesuggestions.SuggestionsView`, or None when the page did not look one up (an error re-render) -- in which case only the button shows, because "no run yet" is a claim this template cannot make. Every proposal carries the CV line it came from. That is the point of the panel: a wrong suggestion should be obvious, not plausible. Nothing here is applied until a button is pressed, and anything the user has already stated is shown beside the suggestion rather than replaced. #}

Read my settings off my CVs

Your CVs already say which disciplines you practise, where you have worked and what level you have been operating at. This reads those off so you can accept each with a click instead of typing them again. It is one cheap call, billed to your own API key, and nothing is recorded until you accept it.

It will never suggest pay, contract type, right to work, notice or anything you would refuse. A CV does not state those, and a guess would put a requirement on your profile that you never made.
